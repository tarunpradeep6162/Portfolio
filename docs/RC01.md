# RC-01: conversational companion

RC-01 is the robot guide in the corner of the site. It has two modes:

- **Offline mode** (always available): guided tours and the documented command
  console. No network, no API key, deterministic.
- **Chat mode** (needs an API key): a general AI assistant powered by Claude.
  It answers any reasonable question (general knowledge, cloud/DevOps, code,
  careers) and is the expert on Tarun: facts about him come only from this
  portfolio's content and cite their source page. It can also act on the page
  (open a case study, scroll, highlight a spine stage, copy the email). Chat
  opens by default on the desktop dock.

If chat is unavailable (no key, outage, rate limit), the panel says so and
points to the console. Nothing else on the site depends on it.

## Setup: pick a brain

RC-01 picks what answers questions from the environment variables in Vercel
(Project → Settings → Environment Variables), in this order:

| Mode | Set this | Cost | What it can answer |
|---|---|---|---|
| **Built-in** (default) | nothing | free | Questions about Tarun (projects, skills, experience, education, certifications, contact), answered straight from `content/` with citations. It says so honestly when a question is outside the portfolio. |
| **Free AI** | `GEMINI_API_KEY` (free at aistudio.google.com/apikey) **or** `GROQ_API_KEY` (free at console.groq.com/keys) | free tier, rate-limited | Anything, plus grounded answers about Tarun. Text only (no page actions). Free tiers may use prompts to improve the provider's models. |
| **Claude** | `ANTHROPIC_API_KEY` | paid | Anything, plus page actions (open pages, scroll, highlight, copy email), with refusal fallbacks. |

If an AI provider fails before it starts answering (quota, outage), RC-01
answers from the built-in engine instead of showing an error.

Other settings:

| Variable | Default | Purpose |
|---|---|---|
| `RC01_FREE_MODEL` | `gemini-3.8-flash,gemini-flash-latest,gemini-flash-lite-latest` | Comma-separated model chain; the next model is tried if one is overloaded, rate-limited or retired. |
| `RC01_MODEL` | `claude-opus-5` | Claude model id. |
| `RC01_EFFORT` | `medium` | Claude effort: `low` / `medium` / `high`. |
| `RC01_VISITOR_LIMIT` | `20` | Requests per visitor per 10 minutes (all modes). |
| `RC01_INSTANCE_HOURLY_LIMIT` | `400` | Requests per server instance per hour (all modes). |
| `RC01_DISABLED` | - | `true` switches chat off entirely. |

Redeploy after changing them.

## How it works

```
Browser (CompanionChat)                  Server (/api/rc01)                   Claude
  question + page context  ── POST ──▶  validate, rate-limit, same-origin
                                        system prompt = persona + site map
                                                      + knowledge base (cached)
                                        ── messages.stream ──────────────────▶
  text chunks  ◀── NDJSON ──            text deltas  ◀────────────────────────
  (spoken sentence by sentence)         tool_use → parseAction() → allowlist
  page actions ◀── NDJSON ──            valid → relay; invalid → is_error
                                        tool_result → next model call (max 3)
```

| Piece | File |
|---|---|
| Knowledge base built from `content/*` | `lib/rc01/knowledge.ts` |
| System prompt and per-request context | `lib/rc01/prompt.ts` |
| Page-action tools (schemas) | `lib/rc01/tools.ts` |
| Action allowlist and validator (shared by server and browser) | `lib/rc01/actions.ts`, `lib/rc01/routes.ts` |
| Wire protocol and request validation | `lib/rc01/protocol.ts` |
| Endpoint (mode selection, Claude path) | `app/api/rc01/route.ts` |
| Built-in answer engine (intents + BM25 retrieval) | `lib/rc01/localBrain.ts` |
| Free-tier provider client (Gemini / Groq) | `lib/rc01/freeProvider.ts` |
| Client streaming hook | `lib/rc01/useRc01Chat.ts` |
| Chat UI | `components/companion/CompanionChat.tsx` |
| Body language signal bus (voice, gaze, gestures, reactions) | `lib/companion/robotSignals.ts` |
| Voice in / voice out | `lib/companion/useVoiceInput.ts`, `lib/companion/useCompanionSpeech.ts` |
| Visitor memory (this device only) | `lib/companion/visitorMemory.ts` |

**Keeping answers accurate.** The knowledge base is generated from the same
typed content the pages render, tagged with each fact's source page. Fields
still marked `needs-input` in `content/` appear as "NOT PUBLISHED YET", so RC-01
says a fact is unpublished instead of inventing one. Updating `content/` updates
RC-01 automatically.

**Caching.** The tools and system prompt are identical on every request
(`tests/unit/rc01-grounding.test.ts` checks this). Anything per-visitor goes in
the latest user turn, so the prompt cache hits across all visitors. Check the
`rc01.usage` log lines in Vercel for `cache_read_input_tokens > 0`.

## Cost and abuse controls

- The same-origin check stops other sites from using the endpoint as a free proxy.
- Rate limits apply per visitor and per server instance. These are in-memory per
  instance: they stop a single visitor or a runaway instance, but not a
  distributed attack. For a hard global cap, also add a Vercel Firewall
  rate-limit rule on `/api/rc01`.
- Each question is capped at 800 characters and the history at 12 turns.
- Each answer is capped at 4,096 tokens, with at most 3 model calls per question.
- `effort: medium` by default.
- Refusal fallback (`fallbacks: "default"`): if the model's safety classifier
  declines a request, the API retries it on its recommended fallback model.
- Every response logs token usage (`rc01.usage`). Messages that look like
  prompt-injection attempts are logged as `rc01.injection_signal`.
- Set a monthly spend limit in the Anthropic Console as a backstop.

## Security model

- Visitor text is treated as a request, never as a change to the rules. RC-01
  won't reveal its prompt, impersonate Tarun or commit on his behalf, share
  private information, or help with clearly harmful requests.
- The model can only suggest actions from a closed list. Each action is
  validated on the server and again in the browser, and navigation only reaches
  real internal pages. Only plain `https` links render as outbound links (new tab, `rel="noopener noreferrer nofollow"`); anything else is shown as plain text.
- Answers never render HTML, and citations are rebuilt from an allowlist.
- No API key, prompt or knowledge base reaches the browser.

## Testing

- `npm test` runs the deterministic suite with no API cost: knowledge base,
  protocol, validators, text/speech splitting, memory, suggestions, speech
  streaming, and the endpoint's full tool loop against a scripted fake SDK
  (`tests/unit/rc01-*.test.ts`).
- `npm run eval:rc01 -- <base-url>` runs the live evaluation: 32 golden
  questions (`tests/rc01-eval/golden.json`) scored on facts, citations,
  forbidden fabrications, refusals and page actions. It costs money on every
  run, so use it after changing the prompt, content or model. It fails below a
  90% pass rate.

## Not included, and why

- **A modelled, rigged 3D character.** RC-01 (v7) is a glossy procedural
  robot with clear-coat materials and studio reflections, built in code. Its body language (blinks, eye movement, gaze, gestures, leaning,
  flinching, speech-synced visor) is procedural. A rigged glTF model from
  Blender with authored animations would be the next visual step, but it needs
  a 3D artist; `RC01Model.tsx` reads the same signals, so a model could replace
  the geometry later.
- **A paid text-to-speech voice.** RC-01 uses the best voice the visitor's
  browser provides (it prefers natural/neural voices) with a fixed pitch and
  rate, so it sounds consistent. A hosted voice service would sound identical
  everywhere but needs another vendor account and a key.
