# Award Experience v4 — implementation plan

## Evidence from the V3 review

V3 is sound, readable, responsive, and honest, but its screenshots still look like a polished developer template. The desktop hero leaves the right half visually unresolved, the WebGL topology is too faint to carry the concept, the global Flightpath resembles reading-progress UI, most sections share the same heading/content rhythm, and the four case studies are structurally interchangeable. The visual system needs more authorship without weakening accessibility or inventing facts.

## Build plan

1. **Replace ambient WebGL with the Infrastructure Observatory.** Build an always-visible, code-generated SVG control surface from the real eight Reliability Spine stages. Retain restrained motion and a complete reduced-motion state while removing the Three.js/R3F client payload.
2. **Recompose the home page.** Use an asymmetric hero, operational status strip, editorial project sequence, a dark Reliability Protocol chapter, compact capability matrix, career proof, and a decisive contact finale. Remove the global progress rail and repetitive section template.
3. **Turn project diagrams into cover art.** Redraw all four real flows as distinct technical compositions with stronger scale, project numbering, visible legends, and meaningful hover motion.
4. **Give routes distinct silhouettes.** Build a catalogue-like Work page, split-layout case studies, editorial About story, print-conscious web résumé, control-room Contact page, and route-loss 404.
5. **Refine the system.** Replace the heavy display face, tune fluid type and spacing, strengthen navigation, reduce generic pills/borders, and add purposeful interaction feedback.
6. **Verify the full story.** Generate Next route types, lint, typecheck, run unit and E2E tests, capture mobile/tablet/desktop screenshots, inspect console/network/overflow, compare the client bundle, and document any factual gaps or unmeasured metrics honestly.

## Non-negotiables

- Branch: `award-experience-v4`; V3 remains untouched.
- No fabricated metrics, achievements, clients, links, credentials, or screenshots.
- Unknown controls stay omitted from public UI and tracked in `CONTENT_GAPS.md`.
- No scroll hijacking, pointer replacement, inaccessible hover-only content, or essential canvas.
- The result may target award-submission quality but cannot claim an award that has not been received.
